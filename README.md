# Mechanical Keyboard Pro

## تصحيح مهم: التطبيق أصبح لوحة مفاتيح نظام (IME) أولاً

المفهوم الأساسي تصحّح: هذا ليس تطبيق تحكم عن بعد بالحاسوب فقط - إنه
**لوحة مفاتيح أندرويد حقيقية (Input Method Editor)** تحل محل لوحة المفاتيح
الافتراضية وتعمل في أي تطبيق (متصفح، دردشة، Termux، ألعاب...) بدون أي اتصال
بحاسوب. الاتصال بالحاسوب أصبح **ميزة إضافية اختيارية**.

## كيف تفتحه وتجربه
1. افتح المجلد في Android Studio ودع Gradle يزامن.
2. شغّل على جهاز/محاكي Android 8+ (المفضّل API 28+ لدعم Bluetooth HID الكامل).
3. أول تشغيل: Splash → شاشة رئيسية (Home) فيها زرّان:
   - **"تفعيل لوحة المفاتيح من إعدادات أندرويد"** → يفتح
     `Settings.ACTION_INPUT_METHOD_SETTINGS` لتفعيل "Mechanical Keyboard Pro".
   - **"اختيارها كلوحة المفاتيح الحالية"** → يفتح منتقي لوحات المفاتيح.
4. بعدها افتح أي تطبيق فيه حقل كتابة - تظهر اللوحة تلقائيًا وتكتب مباشرة.
5. زر إضافي اختياري في الشاشة الرئيسية يفتح تدفق ربط الحاسوب (Bluetooth HID)
   القديم كـ preview/محاكاة للوضع الثانوي.

## كيف تعمل لوحة المفاتيح فعليًا (IME)
- `KeyboardService` يسجَّل في `AndroidManifest.xml` كـ `<service>` بصلاحية
  `BIND_INPUT_METHOD` + `res/xml/method.xml` (subtypes: English, العربية).
- يستضيف `ComposeView` عبر `ImeLifecycleOwner` (IME ليس LifecycleOwner افتراضيًا).
- `onKeyPressed(key)` يوزّع الضغطة حسب نوعها:
  - حروف/أرقام إنجليزية → `InputConnection.commitText` مع مراعاة Shift/Caps Lock.
  - حروف عربية (`ArabicLayout`, action = TEXT_INSERT) → `commitText` مباشرة.
  - مفاتيح PC (`PcKeysLayout`, action = PC_KEY_EVENT) → `InputConnection.sendKeyEvent`
    بأكواد `KeyEvent.KEYCODE_*` حقيقية (ESC, Insert, Home, Page Up...).
  - Ctrl/Alt/Win + مفتاح → يُبنى `metaState` ويُرسل كاختصار حقيقي (مثل Ctrl+C
    داخل Termux أو أي تطبيق يدعمها).
  - مفتاح اللغة 🌐 → `LayerManager.cycleLanguage()` للتبديل الفوري إنجليزي/عربي.

## الحالة الحالية مقابل ترتيب الأولويات المطلوب
1. ✅ IME أندرويد يعمل فعليًا (كتابة حقيقية في أي تطبيق).
2. ✅ واجهة احترافية (نفس Theme/KeyCap/CommandBar من قبل، بارتفاع ثابت مناسب لـ IME).
3. ✅ دعم مفاتيح PC الأساسية (ESC/TAB/CTRL/ALT/WIN/F1-F12/الأسهم/Home/End/Insert/Delete/PageUp/PageDown).
4. ✅ نظام الطبقات: 6 طبقات جاهزة وتعمل - English / العربية / PC Keys / Programming / Gaming / Macros.
   (Office/Custom تُضاف بنفس الطريقة: ملف Layout جديد + تسجيله في LayerManager.)
5. ⬜ التخصيص (تصميم اللوحة بالسحب والإفلات) - لم يبدأ.
6. ✅ محرك الماكرو (`MacroEngine`) مربوط فعليًا بمفاتيح طبقة Macros، عبر تجريد
   `MacroSink` يشغّل نفس الماكرو محليًا (`ImeMacroSink` → يكتب في التطبيق الحالي)
   أو عبر البلوتوث (`BluetoothMacroSink`) بدون أي فرق في تعريف الماكرو نفسه.
   M1-M4 مسجّلة مسبقًا (Copy/Paste/Cut/Alt+Tab)، M5-M8 فارغة لواجهة تسجيل لاحقة.
7. ⬜ تأثيرات RGB الفعلية على المفاتيح (البنية `RgbController` جاهزة، الربط بصريًا لم يتم).
8. ✅ وضع الاتصال بالحاسوب (Bluetooth HID حقيقي) موجود من قبل، أصبح الآن مسارًا
   اختياريًا واضحًا بدل أن يكون الأساس.

## ملاحظات مراجعة شاملة (بعد بلاغ التوقف عند التفعيل كلوحة افتراضية)

راجعت المشروع كامل (49 ملف Kotlin) بحثًا عن أي سبب محتمل للتوقف. اللي لقيته
وصلّحته:

1. **مجلد فاسد فارغ** من أمر `mkdir` قديم (توسّع الأقواس ما اشتغل صح في
   بيئة الأدوات) - كان بدون أي ملفات، حذفته. لم يكن يسبب أي مشكلة فعلية لكنه
   كان يشوّش شجرة الملفات.
2. **كل الـ imports الداخلية (`com.mkpro.keyboard.*`) تحققت آليًا** - 116 رمز
   معرّف، صفر استيراد مفقود، صفر تضارب أسماء مفاتيح داخل أي طبقة.
3. **لم يكن هناك Gradle Wrapper فعلي أصلًا** (`gradlew`, `gradlew.bat`,
   `gradle-wrapper.jar`, `gradle-wrapper.properties`) - على الأغلب هذا أحد
   الأخطاء اللي صلّحتها يدويًا عشان GitHub Actions يبني المشروع. أضفتها الآن
   كاملة وحقيقية (Gradle 8.7، متوافقة مع AGP 8.5.2).
4. **حذفت KSP plugin** من `build.gradle.kts` - كان مُفعّلًا بدون أي معالج
   (processor) يستخدمه فعليًا (لا Room ولا غيره بعد)، مجرد نقطة فشل محتملة
   بلا فائدة حاليًا. يرجع لما نضيف Room فعليًا.
5. **عطّلت `isMinifyEnabled`** في release build (كانت السبب الأرجح للتوقف
   عند التفعيل تحديدًا: R8 بدون قواعد keep كافية يشيل أجزاء من Compose
   المستضاف خارج Activity، أو الـ coroutines، دون ما يعرف إن `KeyboardService`
   نقطة دخول لأنه معروف فقط عبر AndroidManifest).
6. **أزلت الاعتماد على reflection** (`KeyEvent::class.java.getField`) في
   قراءة أكواد مفاتيح PC، واستبدلتها بخريطة مباشرة (`AndroidKeyCodeRegistry`) -
   أكثر أمانًا حتى بدون minification.
7. أضفت `.gitignore` مناسب للمشروع.

**إذا التوقف مستمر بعد هذا** - محتاج تحديدًا نص الخطأ (logcat عند لحظة
التفعيل) عشان أحدد السطر بدقة بدل الاستمرار بالتخمين المدروس.

## السبب الفعلي للكراش (من الإشعار اللي وصلك - CrashReporter اشتغل فعلاً)

النص اللي طلع بالإشعار دقيق جدًا ومفيد:

```
java.lang.IllegalStateException: ViewTreeLifecycleOwner not found from
android.widget.LinearLayout{... android:id/parentPanel}
```

هذا يعني إن Compose كان يبحث عن `ViewTreeLifecycleOwner` بدءًا من View داخل
نافذة الـ IME، لكن البحث ما وصل لـ `composeView` اللي ربطنا عليه
`setViewTreeLifecycleOwner` مباشرة - لأن بعض أجهزة MIUI/بعض إصدارات أندرويد
تُدرج حاويات إطار عمل إضافية بين جذر نافذة الخدمة (`Window.decorView`)
والـ View اللي نرجعه من `onCreateInputView()`. لما يبدأ البحث من إحدى تلك
الحاويات (هنا LinearLayout بمعرف `parentPanel`) قبل ما يوصل لـ composeView
نفسه، ما يلقى أي owner مربوط.

**الإصلاح:** ربطت الـ `ViewTreeLifecycleOwner` على `window.window.decorView`
نفسه (جذر النافذة الحقيقي) مو بس على `composeView` - في `onCreateInputView()`
وأيضًا بشكل دفاعي في كل `onStartInputView()` (لأن النافذة ممكن تُعاد بين
جلسات الكتابة). هذا يضمن إن أي View داخل نافذة الخدمة - سواء أنشأناه إحنا
أو أضافه إطار العمل/الشركة المصنّعة - يقدر يوصل لـ lifecycle owner صحيح.

هذا أقوى إصلاح حصل لحد الآن لأنه مبني على نص الاستثناء الفعلي، مو تخمين.

**تحديث:** بعد هذا الإصلاح ظهر استثناء ثانٍ حقيقي عبر نفس الإشعار:
`Composed into the View which doesn't propagate ViewTreeSavedStateRegistryOwner!`
عند `AndroidComposeView.onAttachedToWindow`. تبيّن إن التبسيط اللي سويته
بمرحلة سابقة (حذف `SavedStateRegistryOwner` بحجة إنه غير مستخدَم) كان خطأ:
Compose يتطلب `ViewTreeSavedStateRegistryOwner` بشكل إلزامي دائمًا عند أول
attach لأي `ComposeView`، بغض النظر عن استخدام `rememberSaveable` من عدمه -
هذا شرط داخلي في Compose نفسه مو خيار. أعدت `SavedStateRegistryOwner` لـ
`ImeLifecycleOwner` ورجعت مكتبة `savedstate-ktx`، وربطتها بنفس طريقة إصلاح
الـ decorView أعلاه (على composeView وعلى نافذة الخدمة معًا). أبقيت
`ViewModelStoreOwner` محذوفة فعليًا لأنها الوحيدة غير المطلوبة فعلًا (فقط
لو استُخدم `viewModel()`، وهذا غير موجود بالكود).

## إصلاحات تجربة الاستخدام (بعد أول تجربة كتابة ناجحة)

1. **حجم الخط صغير** - رفعت خط تسمية المفاتيح من 11sp إلى 15sp (`KeyCap.kt`)،
   وزدت ارتفاع منطقة المفاتيح من 220dp إلى 260dp عشان يبقى فيه مساحة كافية
   بدون تداخل أي مفتاح فوق الثاني.
2. **الكيبورد يظهر تحت أزرار التحكم (وضع ملء الشاشة)** - سببين محتملين
   عالجتهما معًا:
   - عطّلت وضع "Extract Mode" الافتراضي لـ `InputMethodService`
     (`onEvaluateFullscreenMode() = false`) - بعض الشاشات/واجهات الشركات
     المصنّعة تفعّله تلقائيًا وهو يتصرف كنافذة مختلفة كليًا.
   - أضفت `.navigationBarsPadding()) على المحتوى الرئيسي حتى يحسب مساحة شريط
     التنقّل (خصوصًا مع اللمس الإيمائي/Gesture Navigation) ولا يرسم تحته.
3. **زر الحذف (Backspace) لا يكرر عند الضغط المطول** - أضفت دعم "الضغط
   المطوّل المتكرر" في `KeyCap.kt`: أول ضغطة تحذف فورًا، وبعد تأخير قصير
   (350ms) يبدأ يحذف كل 50ms طالما الإصبع لسا ضاغط - نفس سلوك أي كيبورد
   حقيقي. باقي المفاتيح لم يتغيّر سلوكها (تحذف/تكتب عند الرفع كالمعتاد).

## تأثيرات RGB الفعلية على المفاتيح

كل مفتاح الآن يرسم توهجه الحقيقي حسب التأثير المختار في الإعدادات، بساعة
رسوم متحركة واحدة مشتركة لكامل اللوحة (`rememberInfiniteTransition` واحد في
`KeyboardIme`/`KeyboardScreen`، وليس واحد لكل مفتاح - أخف على الأداء):

- **Static**: لون ثابت بسطوع محدد
- **Breathing**: نبض سلس بين خافت وساطع (منحنى جيبي حقيقي)
- **Rainbow**: تدرّج ألوان مستمر (HSV) يختلف قليلاً حسب موضع كل مفتاح
- **Wave**: موجة سطوع تتحرك فعليًا عبر صفوف وأعمدة لوحة المفاتيح (كل مفتاح
  يحسب طوره الخاص حسب موضعه)
- **Reactive**: يضيء المفتاح فقط لحظة الضغط عليه
- **Ripple**: مثل Reactive حاليًا (نسخة مبسّطة - تموّج دائري فعلي من نقطة
  الضغط يحتاج معرفة الإحداثيات الفعلية للمفتاح، مو بس رقمه في القائمة؛
  خطوة تالية منطقية)

اللون والتأثير والسطوع والسرعة كلها تُقرأ فعليًا من `AppSettings` (محفوظة
عبر DataStore)، وأي تغيير في شاشة الإعدادات ينعكس فورًا على شكل اللوحة -
سواء وضع الكتابة العادي أو معاينة وضع الحاسوب.

## إعادة تصميم بصرية كاملة (حسب المرجع المرسل)

- **رأس علامة تجارية جديد** (`BrandHeaderBar`): أيقونة قائمة، شعار سطرين
  "MECHANICAL / KEYBOARD PRO" (السطر الثاني بلون المود النشط)، وزرّان
  دائريان على اليمين.
- **لون هوية ثابت لكل مود** (`accentColorFor` في `LayerAccent.kt`) - مختلف
  عن لون RGB الذي يختاره المستخدم: سماوي للكتابة العادية، بنفسجي لـ PC
  Keys، برتقالي للـ Gaming، أزرق لـ Programming. هذا اللون يلوّن التبويبات
  وحدود المفاتيح الخاصة وشريط الوضع السفلي - بغض النظر عن ثيم/RGB المستخدم.
- **شريط تبويبات المود** (`ModeTabRow`) - مجموعة الأيقونات تتغيّر حسب
  الطبقة النشطة (لوحة مفاتيح/ثيم/حافظة/إيموجي للكتابة، لعبة/ماكرو/بروفايل/
  RGB للـ Gaming، كود/حافظة/AI/مقتطفات للبرمجة...). **تنبيه صريح**: أيقونة
  المود نفسه فقط مفعّلة فعليًا الآن - البقية (حافظة، إيموجي، أدوات AI،
  مقتطفات) عناصر بصرية جاهزة تقود لشاشة الإعدادات مؤقتًا، مو ميزات مبنية
  فعلاً (تحتاج مدير حافظة/منتقي إيموجي حقيقي - غير مبني بعد).
- **صف تبديل اللغة** (`LanguageSwitcherRow`) - نقطة خضراء + رمز اللغة +
  أسهم للتنقل، يظهر فقط في طبقات الكتابة (إنجليزي/عربي). أزلت مفتاح 🌐 من
  صفوف المفاتيح نفسها لأنه صار مكرر مع هذا الشريط + شريط الأسفل.
- **مفاتيح خاصة بحدود لونية دائمة** - Shift/Backspace/Enter الآن لها حدود
  خفيفة بلون المود حتى بدون ضغط، وتصبح ساطعة كاملة عند التفعيل (بدل ما
  تكون عادية تمامًا حتى الضغط).
- **شريط سفلي جديد** (`BottomActionBar`) - أيقونة كرة أرضية (تبديل اللغة)،
  حبة مركزية باسم المود الحالي بلون المود، وأيقونة مايكروفون. **المايكروفون
  عنصر بصري فقط حاليًا** - الإدخال الصوتي يحتاج ربط `SpeechRecognizer` غير
  مبني بعد.
- **حذفت `CommandBar.kt` القديم بالكامل** (حل محله `BrandHeaderBar` +
  `ModeTabRow`)، وطبّقت نفس النظام على وضع الكتابة العادي **ومعاينة وضع
  الحاسوب** معًا - نفس الشكل بالضبط في كل الأوضاع.
- أثناء هذا العمل، لقيت وصلّحت **علّة حقيقية في إعادة التفاعلية**:
  `KeyboardViewModel` كان يراقب تغيّرات قائمة الطبقات فقط، مو تغيّر الطبقة
  النشطة - يعني تبديل الطبقة في معاينة وضع الحاسوب كان ممكن ما ينعكس على
  الواجهة فعليًا. صلّحتها بدمج (`combine`) كلا التدفّقين.

## آلية جديدة: التطبيق يعرض الخطأ الحقيقي بنفسه (بدون adb/logcat)

بما إنه ما فيه وصول لجهازك مباشرة، أضفت **مبلّغ أعطال عالمي** (`CrashReporter`)
يشتغل بدون أي أداة خارجية:

- يُثبَّت أول شيء في `MkProApplication.onCreate()` عبر
  `Thread.setDefaultUncaughtExceptionHandler` - يعني يلتقط **أي** استثناء غير
  معالَج بأي مكان بالتطبيق، مو بس داخل دالة وحدة.
- عند حدوث كراش، **قبل** ما يظهر نظام أندرويد نافذة "توقف التطبيق"، يظهر
  إشعار بعنوان "Mechanical Keyboard Pro crashed" - اضغط عليه ليتوسّع ويطلع
  لك نوع الاستثناء + الرسالة + أول جزء من الـ Stack Trace كامل نصيًا.
- يحتاج صلاحية إشعارات (`POST_NOTIFICATIONS`, API 33+) - يُطلب تلقائيًا أول
  ما تفتح التطبيق، **لازم توافق عليها** وإلا ما يقدر يعرض الإشعار.
- بالإضافة لذلك، `onCreateInputView()` نفسه محاط بـ try/catch: لو فشل بناء
  الواجهة بشكل متزامن، يظهر نص خطأ بسيط (View عادي، مو Compose) بدل شاشة
  فارغة أو كراش صامت. هذا يغطي فقط الفشل المتزامن أثناء البناء - أي فشل لاحق
  في أول رسم/تخطيط لـ Compose (يحدث بشكل غير متزامن بعد رجوع الدالة) يغطّيه
  `CrashReporter` فقط.

**الخطوة المطلوبة منك:** أعد البناء، ثبّت، افتح التطبيق مرة وامنح صلاحية
الإشعارات، فعّل اللوحة، وجرّب الكتابة. لو صار كراش، افتح شريط الإشعارات
وصوّرلي الإشعار موسّعًا بالكامل - هذا يحوّل أي إصلاح قادم من تخمين إلى حل
مباشر لسطر الكود الفعلي.

## إصلاح أخطاء بناء حقيقية (من سجل GitHub Actions الفعلي)

هذه أول مرة توفر فيها سجل بناء حقيقي - والنتيجة إصلاحات مؤكدة 100%، لا تخمين:

1. **`Cannot access 'weight': it is internal in 'androidx.compose.foundation.layout'`**
   في `KeyboardIme.kt` و`KeyboardScreen.kt`. السبب: `weight()` هي دالة عضو
   داخل واجهتي `RowScope`/`ColumnScope` نفسهما (مو دالة توسيع top-level)،
   فاستيرادها صراحة بـ `import androidx.compose.foundation.layout.weight`
   خطأ - يتم حلّها تلقائيًا عبر الـ receiver الضمني داخل `Row { }`/`Column { }`
   بدون أي import. حذفت سطر الاستيراد الخاطئ من الملفين (كذلك تحققت إن
   `KeyCap.kt` لم يكن يستورده أصلًا، ولهذا لم يتعطل).
2. **`Unresolved reference: LocalLifecycleOwner`** في `SplashScreen.kt` -
   سطر كود ميت (`val lifecycleOwner = LocalLifecycleOwner.current`) بقي من
   مرحلة سابقة بعد ما حذفت الـ import المرتبط به ونسيت حذف الاستخدام.
   محذوف الآن بالكامل (لم يكن يُستخدم لأي شيء).
3. تحقّقت بحث شامل عن أي استيراد آخر لدوال أعضاء RowScope/ColumnScope/BoxScope
   بنفس النمط (مثل `align`) - لا يوجد غيرها.
4. أضفت `android.suppressUnsupportedCompileSdk=35` في `gradle.properties`
   لإسكات تحذير AGP 8.5.2 (تحذير فقط، لم يكن يوقف البناء).

يجلبه compose-bom تلقائيًا نمط تعطّل حقيقي ومعروف (NoSuchMethodError وقت
التشغيل فقط)، وإزالة غير المستخدَم يزيل هذا الاحتمال بالكامل بدل مجرد تقليله.
